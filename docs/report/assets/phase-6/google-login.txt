3. DEPLOY
==============================================================================
  cd infra && set -a && . ./.env.seed-demo && set +a && ./scripts/deploy.sh

Lượt 1: build đủ 5 image, rồi BuildKit rớt ("target worker: failed to receive
status: rpc error: code = Unavailable desc = error reading from server: EOF").
Ngay sau đó Docker Engine trả 500 cho mọi lệnh và https://devpath-01.me trả
530 (Cloudflare không gọi được về máy). Đây là kiểu chết Docker Desktop đã
biết trên máy này: chạy C:\Users\Admin\start-docker.ps1 → engine lên lại, 13
container của stack demo tự khởi động, site 200, readiness 200.

Lượt 2: build lại từng image một (`compose build <service>`) → cả 5 lấy từ
cache, mỗi cái ~4 s, tức lượt 1 đã build xong. `deploy.sh` exit 0: migrate,
healthy, API ↔ CSDL/Redis/bucket, cloudflared kết nối, hỏi
https://devpath-01.me/api/v1/health/ready từ bên ngoài qua Cloudflare. Vẫn
đúng một connector (không có container cloudflare/cloudflared:latest nào).

Bài học cho buổi GVHD: đừng deploy sát giờ trình bày. Docker Desktop 8 GB vừa
chạy stack demo vừa build 5 image song song có thể chết, và site tắt theo.

6. TÌM RA: IP THẬT CỦA NGƯỜI DÙNG MẤT SAU TUNNEL (chưa sửa)
==============================================================================
Cả hai dòng refresh_tokens của phiên trên ghi ip_address = 172.20.0.8, tức
IP của container devpath-demo-cloudflared-1 trên mạng compose, không phải IP
của người dùng.

Nguyên nhân: infra/nginx/snippets/proxy.conf ghi đè X-Forwarded-For bằng
$remote_addr (sửa 01/10 để client không tự chọn IP). Trên VPS thật nginx là
chặng đầu nên đúng; sau named tunnel, chặng ngay trước nginx là cloudflared.
Comment trong tệp đã đoán trước: "If a CDN is ever put in front of nginx,
this becomes the CDN's address and has to be taken from the CDN's own header
instead, behind set_real_ip_from."

Hệ quả trên https://devpath-01.me:
  - Giới hạn theo IP (đăng ký 50/giờ/IP, đăng nhập 100/15 phút/IP) bị mọi
    khách dùng chung một suất. Cả phòng cùng đăng ký thì người thứ 51 trong
    giờ nhận 429 AUTH_RATE_LIMITED. Giới hạn theo email/tài khoản không đổi.
  - Cột refresh_tokens.ip_address ghi cùng một IP nội bộ cho mọi người.
Hướng sửa (task riêng): khi chạy sau tunnel, nginx lấy IP từ CF-Connecting-IP
nhưng chỉ tin header đó nếu request đến từ cloudflared (`set_real_ip_from`
đúng mạng của nó + `real_ip_header CF-Connecting-IP`), còn VPS không tunnel
giữ nguyên như cũ. Không đổi trong task này vì đụng cấu hình bảo mật của nginx.
